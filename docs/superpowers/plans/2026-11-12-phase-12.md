# Phase 12 (0.10.0) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** remplacer les onglets terminal de Claude par un chat graphique GTK, avec un panneau
Fichiers, la feuille de route, une page Projets, une navigation en 4 onglets et un design
repris, sans perdre aucune fonction des terminaux.

**Architecture :** comme aujourd'hui, la logique sans GTK (protocole, moteur du chat, Markdown,
feuille de route, git, fichiers, couleurs) vit dans `ccs_app/*.py` et se teste sans affichage.
Les widgets vivent dans `ccs_app/gui/*.py`. Le chat pilote `claude -p` en stream-json (moteur
`chat_engine`). L'onglet de chat présente à la page Terminaux la même interface qu'un
`TerminalTab` : un `terminal.TabState` tenu à jour. Toute la logique existante (file de
messages, reprise après une limite, alertes, compte des sessions qui attendent) marche donc
sans changement.

**Tech Stack :** Python 3.12, PyGObject 3.48, GTK 4.14, libadwaita 1.5, GtkSourceView 5
(`gir1.2-gtksource-5`), markdown-it-py 3.0 (`python3-markdown-it`), VTE 3.91 (shells et sortie
de secours), unittest, Xvfb.

**Spec :** `docs/superpowers/specs/2026-11-12-phase-12-design.md`. Le lire en entier avant
toute tâche. Pour le protocole, le rapport d'essai réel prévaut sur l'annexe :
`/tmp/claude-1000/-home-charles-gamligo/838f8062-6084-4e11-bdd5-a09c0cd8b2c7/scratchpad/essai-protocole/RAPPORT.md`.
Ses jeux d'essai anonymisés sont copiés dans `tests/fixtures/chat/` (tâche 1).

## Review Focus

1. **Lignes énormes et longues conversations.** Un `tool_result` de 2 Mo sur une ligne, ou 1 000 messages dans un chat rouvert : rien n'est tronqué ni perdu, l'interface ne fige pas. Test dans la tâche 2 (`test_two_megabyte_line_is_parsed`) et dans la tâche 7 (`test_thousand_messages_build_lazily`).
2. **`claude` qui meurt au lancement** : binaire absent, compte déconnecté, option refusée. Le chat montre l'erreur, avec la fin de stderr, puis un bouton « Relancer ». L'onglet ne reste pas en « busy ». Tests `test_process_dies_at_start` (tâche 2) et `test_start_failure_shows_notice` (tâche 7).
3. **Fichiers hostiles dans l'arbre** : fichier non UTF-8, binaire, de plus de 2 Mo, supprimé pendant qu'il est ouvert, boucle de liens symboliques. On voit un message, rien ne plante, l'arbre ne boucle pas. Tests de la tâche 5.
4. **`ROADMAP.md` atypique** : fins de ligne CRLF, tâches imbriquées, tâche hors phase, deux tâches au même texte. Un clic change exactement un caractère sur la bonne ligne. Tests de la tâche 4.
5. **Projet hors git ou git absent** : la carte du projet s'affiche quand même (sans versions) et rien ne lève. Test `test_not_a_git_repo` (tâche 4).

### Task 2 : Moteur du chat (sans GTK)

**Files :**
- Create : `ccs_app/chat_engine.py`, `tests/test_chat_engine.py`

**Interfaces :**
- Consumes : tâche 1 ; `terminal.SESSION_VARS`, `task_runner.environment()`, `sessions._claude_bin()`.
- Produces : `class ChatSession`
  - `__init__(cwd, session_id=None, options=ChatOptions(), on_event=None, claude=None, environ=None, clock=time.time)`. `on_event(ev)` est appelé **depuis un fil de lecture** : l'interface l'enveloppe dans `GLib.idle_add`.
  - `state` vaut `"stopped" | "starting" | "idle" | "busy" | "permission" | "suspended"`. Chaque changement émet `StateChanged(state)`, un événement propre au moteur.
  - Attributs : `session_id`, `options`, `last_activity: float`, `pid: int|None`, `started_at: float|None`.
  - `send(text, images=()) -> bool` : lance le processus s'il le faut (`--resume` si `session_id`), puis envoie le message. Il renvoie False sans rien écrire si l'état est `busy` ou `permission`, car l'essai n'a pas pu établir ce que fait la CLI d'un message reçu pendant un tour. Le moteur n'a **pas de file à lui**. La file visible et modifiable reste `TabState.queue`, gérée par `TerminalsPage.send_queue` comme pour les terminaux.
  - Après `interrupt`, la CLI finit le tour (`interrupted`) puis s'arrête avec le code 1. C'est un arrêt demandé : l'état passe à `"stopped"` sans encart d'erreur, et le prochain `send` relance par `--resume`.
  - Au lancement, le moteur envoie `initialize` avant tout message, et émet `Hello`.
  - `interrupt()` : requête `interrupt`.
  - `answer(request_id, decision: "allow"|"always"|"deny", message="")`.
  - `set_options(options)` :
    - modèle et droits passent en direct (`set_model`, `set_permission_mode`) ;
    - effort et ultracode passent par `/effort <niveau>`, `/effort ultracode` ou `/effort ultracode off`, des commandes locales sans tour de modèle, envoyées avant le prochain message et dont le `LocalCommand` n'est pas montré comme une réponse ;
    - le moteur retient lui-même l'effort en cours, que la CLI n'annonce jamais.
  - `request_context()` : `get_context_usage`, rendu par `ContextUsage(percentage, total, maximum)`, un événement propre au moteur.
  - `suspend_if_idle(now, idle_s) -> bool` : arrête le processus si `state == "idle"` depuis `idle_s`, sans autorisation en attente ni outil de fond ; l'état passe à `"suspended"`. Le prochain `send` relance par `--resume`.
  - `stop(grace_s=5)` : ferme stdin, attend `grace_s`, SIGTERM sur son pid, attend `grace_s`, puis SIGKILL.
  - `ProcessExited(code, stderr_tail)` : événement propre au moteur, avec les 20 dernières lignes de stderr.
- Lancement : `argv = [claude, "-p", "--input-format", "stream-json", "--output-format", "stream-json", "--verbose", "--include-partial-messages", <options d'autorisation du rapport>, *chat_options.launch_args(options), ("--resume", id)]`. Le processus tourne dans `cwd`, avec l'environnement de `task_runner.environment()`, sans `SESSION_VARS`. La lecture de stdout se fait par lignes sans limite de longueur ; stderr est lu dans un autre fil.

### Task 4 : Feuille de route et projets (sans GTK)

**Files :**
- Create : `ccs_app/roadmap.py`, `ccs_app/projects.py`, `tests/test_roadmap.py`, `tests/test_projects.py`

**Interfaces :**
- Produces (`roadmap`) :
  - `Task(text, done, line: int, depth: int)`, `Phase(title, version: str|None, tasks: list[Task], line: int)` avec les propriétés `done_count`, `total` et `finished` ;
  - `Roadmap(title, phases, path)` ;
  - `find(cwd) -> Path|None` : `ROADMAP.md` dans `cwd`, puis en remontant jusqu'à la racine git (exclue au-delà) ;
  - `parse(text, path=None) -> Roadmap` : les phases sont les titres `##` ayant au moins une case ; `version` est le contenu de la dernière paire de parenthèses du titre contenant un chiffre ; les tâches hors phase sont ignorées ;
  - `toggle(path, line: int, expected_text: str) -> bool` :
    - relit le fichier ;
    - vérifie que la ligne `line` est bien une case dont le texte vaut `expected_text` ;
    - remplace uniquement le caractère entre crochets ;
    - garde les fins de ligne (CRLF compris) ;
    - écrit de façon atomique en gardant les droits ;
    - renvoie False si la ligne ne correspond plus (fichier changé entre-temps) ;
  - `newly_done(before: Roadmap, after: Roadmap) -> list[Task]`, reconnues par (titre de phase, texte, rang parmi les homonymes).
- Produces (`projects`) :
  - `Project(path, name, roadmap_path, version, last_activity, current_phase: Phase|None, done, total)` ;
  - `list_projects(convs, hidden=()) -> list[Project]` : les dossiers distincts des conversations (`conversations.scan()`) qui ont un `ROADMAP.md` (`roadmap.find`), triés par dernière activité ;
