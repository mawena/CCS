# Phase 14 (0.12.0) — plan de construction (ex-phase 13)

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development
> (recommandé) ou superpowers:executing-plans, tâche par tâche. Les étapes utilisent des
> cases (`- [ ]`) pour le suivi.

**But :** travailler sans quitter CCS : page Git façon GiGit, tâches de la feuille de
route lancées d'un clic, changements de la session et retour en arrière, quatre ajouts au
chat, autorisations depuis le téléphone.

**Architecture :** chaque chantier a un module sans GTK (testé en unitaire) et une vue
GTK4 (testée sous Xvfb), raccordée à `SessionWorkspace` ou `ChatTab`. git est appelé en
ligne de commande ; l'historique des fichiers est lu dans les copies de Claude Code ;
le téléphone passe par ntfy.

**Technique :** Python 3, GTK4 / libadwaita (PyGObject), GtkSourceView 5, `unittest`,
commande `git` et `git flow` du système, ntfy (HTTP).

**Conception :** `docs/superpowers/specs/2026-11-15-phase-13-design.md` (validée le
15/11/2026). Lire les deux documents avant de commencer.

## Contraintes globales

- Branche `feature/phase14` (née `feature/phase13`, renommée le 15/11 quand la partie VPS est passée en phase 13).
- Tout en français : textes, docstrings, commentaires, commits conventionnels, sans
  `Co-Authored-By` ni attribution.
- Tests : `unittest`, fichiers `tests/test_<module>.py` (unitaires) et
  `tests/test_<module>_gui.py` (graphiques, `@unittest.skipUnless(GTK, …)` avec
  `tests.helpers.gui_ready()`).
- Aucun test hors de la file Gagarine. Unitaire :
  `gagarine file "ccs-t-<nom>" 1 1 -- python3 -m unittest tests.test_<nom> 2>&1 | tail -5`.
  Graphique :
  `gagarine file "ccs-t-<nom>" 1 1 -- sh -c 'CCS_GUI_TESTS=1 xvfb-run -a python3 -m unittest tests.test_<nom>_gui' 2>&1 | tail -5`.
  Suite complète : une seule fois, par `make deb` (tâche 20).
- Les tests git créent leurs dépôts dans `tempfile.mkdtemp()` (`git init`, identité
  locale `-c user.name=Test -c user.email=test@example.org`) ; le distant est un dépôt nu
  local en `file://`. Jamais le dépôt de CCS ni un projet de Charles.
- Jamais de vrai réseau (avatars, ntfy) : `urlopen` injecté, comme `phone.deliver`.
- Jamais le vrai `~/.claude` : `HOME`, `CLAUDE_CONFIG_DIR`, `CCS_HOME` dans un dossier
  temporaire (`tests.helpers.make_home`).
- Tout appel git, réseau ou disque lent passe par `ccs_app.gui.common.in_thread`, jamais
  dans le fil de l'interface.
- Toute action qui détruit du travail (annuler, revenir en arrière, push forcé, finir une
  branche git flow) demande une confirmation (`Adw.AlertDialog`).
- Réglages nouveaux dans `settings.DEFAULTS`, validés par `_clean` comme les autres :
  `"git": {"layout": "A", "fetch_minutes": 5, "avatars": True}` (`layout` dans
  `("A", "B", "C")`, `fetch_minutes` entier de 0 à 1440) et, dans `"phone"`,
  `"show_content": False` et `"reply_topic": ""`.

## Points de vigilance

1. **Dépôt sans commit, ou dossier qui n'est pas un dépôt git.** La page Git montre un
   écran vide (« Pas un dépôt git » ou « Aucun commit »), sans erreur ni trace. Tests :
   tâche 1 (`test_log_empty_repo`, `test_not_a_repo`), tâche 8.
2. **Nom de fichier avec espace, accent ou guillemet**, et fichier binaire dans un diff.
   L'indexation, l'annulation et le diff marchent ; le binaire affiche « Fichier
   binaire ». Tests : tâche 1 (`test_status_odd_names`), tâche 2
   (`test_stage_lines_odd_name`).
3. **Fichier modifié par Charles après le message** vers lequel on revient. La
   confirmation le signale, et rien n'est écrit sans son accord. Test : tâche 11
   (`test_rewind_flags_user_edit`).
4. **Réponse du téléphone rejouée ou arrivée trop tard** (jeton déjà servi, expiré, ou
   autorisation déjà réglée sur le PC). Elle est ignorée. Tests : tâche 17.
5. **Commande `!` qui ne finit pas ou qui écrit énormément.** Le chat reste fluide, la
   commande s'arrête par le bouton, la sortie est tronquée avec la mention. Test :
   tâche 16 (`test_run_truncates`, `test_stop`).

- `parse_diff(raw: bytes) -> list[FileDiff]`.
- `diff(repo, path, staged: bool) -> FileDiff | None` (non suivi : diff contre

- `show(repo, cid) -> tuple[Commit, list[FileDiff]]`.

### Task 2: écritures git (`git_repo`)

**Fichiers :**
- Modifier : `ccs_app/git_repo.py`
- Test : `tests/test_git_repo.py`

**Interfaces produites :**
- `stage_file(repo, path)`, `unstage_file(repo, path)`, `discard_file(repo, fs:
  FileStatus)` (non suivi : suppression du fichier ; sinon `git checkout -- path`, ou
  `git restore --source=HEAD --staged --worktree` s'il est indexé).
- `patch_for(fd: FileDiff, keep: set[tuple[int, int]]) -> bytes` : correctif ne gardant
  que les lignes `(hunk_index, line_index)` choisies. Algorithme (non déterminé par les
  tests) : une ligne `+` non choisie disparaît ; une ligne `-` non choisie devient une
  ligne de contexte ; les en-têtes `@@` sont recalculés ; les blocs sans ligne choisie
  sont omis.
- `stage_lines(repo, fd, keep)` (`git apply --cached --unidiff-zero=false`),
  `unstage_lines(repo, fd, keep)` (`--cached -R`), `discard_lines(repo, fd, keep)`
  (`git apply -R`, sur la copie de travail).
- `commit(repo, message, amend=False) -> str` (renvoie l'id) ; `last_message(repo) -> str`.
- `ignore(repo, relpath)` : ajoute `/relpath` au `.gitignore` de la racine (crée le
  fichier, pas de doublon, termine par un saut de ligne).
- `fetch(repo)` (`--prune`, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=` vide,
  `SSH_ASKPASS=` vide, `ssh -o BatchMode=yes` par `GIT_SSH_COMMAND`) ; `pull(repo)`
  (`--ff-only`) ; `push(repo, force=False)` (sans upstream : `--set-upstream origin
  <branche>` ; forcé : `--force-with-lease --force-if-includes`).
- `flow_available() -> bool` (`git flow version`) ; `flow(repo, kind, action, name=None)`
  avec `kind` dans `("feature", "release", "hotfix")`, `action` dans `("start",
  "finish")` ; `finish` passe `-m <name>` pour `release`/`hotfix` et
  `GIT_MERGE_AUTOEDIT=no`.
- `propose_message(repo) -> str` : d'après les fichiers indexés seulement. Une ligne de
  titre conventionnelle (`chore:` par défaut ; `docs:` si tout est `*.md` ou `docs/` ;
  `test:` si tout est sous `tests/`), puis la liste `- <A|M|D|R> <chemin>`.

### Task 10: lecture de l'historique des fichiers (`file_history`)

**Fichiers :**
- Créer : `ccs_app/file_history.py`

**Format lu** (non documenté, observé dans Claude Code) : lignes
`{"type": "file-history-snapshot", "messageId": <uuid du message>, "snapshot":
{"messageId", "trackedFileBackups": {<chemin absolu>: {"backupFileName": "<hash>@v<n>" |
null, "version": n, "backupTime": iso}}, "timestamp"}, "isSnapshotUpdate": bool}`. Une
ligne `isSnapshotUpdate: true` remplace l'instantané de même `messageId`. Copies :
`<CLAUDE_CONFIG_DIR ou ~/.claude>/file-history/<session>/<backupFileName>`.
`backupFileName: null` : le fichier n'existait pas.

Avant d'écrire, vérifier ce format sur un vrai journal de Charles en ne lisant que les
clés (`jq 'keys'`, jamais le contenu des messages ni des copies), et noter tout écart.

**Interfaces produites :**
- `@dataclass Backup(path: str, name: str | None, version: int)`.
- `@dataclass Snapshot(message_id: str, time: str, files: dict[str, Backup])`.
- `read(transcript: Path) -> list[Snapshot] | None` : dans l'ordre du journal ; None si
  aucune ligne ne suit le format (format inconnu).
- `backup_text(session_id: str, b: Backup) -> bytes | None`.
- `@dataclass Change(path, before: bytes | None, now: bytes | None)` ;
  `changes(snaps, session_id) -> list[Change]` : `before` = plus ancienne copie connue du
  fichier (état avant la conversation) ; `now` = contenu actuel (None si absent) ; seuls
  les fichiers où ils diffèrent.
- `@dataclass Step(path, content: bytes | None, user_edited: bool)` (`None` = supprimer) ;
  `rewind_plan(snaps, session_id, message_id) -> list[Step]`. Algorithme (non déterminé
  par les tests seuls) : pour chaque fichier jamais suivi, si l'instantané de
  `message_id` le contient, son contenu cible est cette copie ; sinon (suivi pour la
  première fois après ce message), la cible est sa plus ancienne copie. `user_edited` est
  vrai si le contenu actuel ne correspond à aucune copie de ce fichier, ni au dernier
  état connu.
- `apply(steps)` : écrit ou supprime ; écrit d'abord dans un fichier temporaire du même
  dossier, puis `os.replace`.
- `check() -> tuple[bool, str]` pour `ccs doctor` : lit le journal le plus récent qui
  contient des instantanés ; « format reconnu » ou « format inconnu ».
